Q1(b)
During the Hospital Management System pipeline, the Maven build may fail
because of compilation errors. How do you solve this?

STEP 1 — Run the Jenkins build

Open:

Jenkins
→ Hospital-Management-Pipeline
→ Build Now
→ Console Output

Find the compilation error.

Common examples:

cannot find symbol
package ... does not exist
incompatible types
invalid target release

STEP 2 — Check Java version

java -version
mvn -version

Make sure Maven uses the Java version required by the project.

STEP 3 — Clean old Maven output

mvn clean

STEP 4 — Build again

mvn clean package

STEP 5 — Fix the actual source/dependency error

If a class or method is missing:
→ correct the class name/method call.

If an import is missing:
→ add the required import.

If a dependency is missing:
→ correct/add the dependency in pom.xml.

If the Java version is wrong:
→ configure Jenkins to use the required JDK.

STEP 6 — Check pom.xml

Check:
- groupId
- artifactId
- version
- dependencies
- compiler configuration

STEP 7 — Test locally

mvn clean test
mvn clean package

STEP 8 — Commit and push the fix

git add .
git commit -m "Fix Maven compilation errors"
git push

STEP 9 — Run Jenkins again

Build Now
→ Console Output

Expected:

BUILD SUCCESS

EXAM ANSWER:
Read the Maven console output, identify the first real compilation error,
check Java/Maven versions and dependencies, correct the source code or
pom.xml, test with Maven, push the fix to GitHub, and rerun Jenkins.

node {

Q3(a)
Run the Hospital Management System inside Kubernetes using Minikube.
Create a deployment using the application Docker image and verify the
application pod is running successfully.

STEP 1 — Start Minikube

minikube start

STEP 2 — Check Minikube

minikube status

STEP 3 — Check Kubernetes node

kubectl get nodes

STEP 4 — Check application image

docker images

Find the application image name.

Example:

hospital-management:1.0

STEP 5 — Create YAML

Create:

hospital-deployment.yaml

Content:

apiVersion: apps/v1
kind: Deployment
metadata:
  name: hospital-app
spec:
  replicas: 1
  selector:
    matchLabels:
      app: hospital-app
  template:
    metadata:
      labels:
        app: hospital-app
    spec:
      containers:
      - name: hospital-container
        image: hospital-management:1.0
        ports:
        - containerPort: 80

Replace hospital-management:1.0 with the actual application Docker image.

STEP 6 — Apply

kubectl apply -f hospital-deployment.yaml

STEP 7 — Check Deployment

kubectl get deployments

STEP 8 — Check Pods

kubectl get pods

Expected:

hospital-app-xxxxx    1/1    Running

STEP 9 — Describe pod

kubectl describe pod <pod-name>

STEP 10 — Check logs if required

kubectl logs <pod-name>

Q3(e)
Application pod repeatedly restarts and becomes unavailable.
Identify the cause and troubleshoot it.

STEP 1 — Check pod status

kubectl get pods

Look for:

CrashLoopBackOff
Error
ImagePullBackOff
ErrImagePull
Pending

Also look at:

RESTARTS

STEP 2 — Describe pod

kubectl describe pod <pod-name>

Important section:

Events

STEP 3 — Check logs

kubectl logs <pod-name>

If the container has restarted:

kubectl logs <pod-name> --previous

STEP 4 — Identify cause.

IMAGE ERROR:

If:

ImagePullBackOff
ErrImagePull

Check:

docker images

Verify image name in the YAML.

If the image exists only in the local Docker environment, load it into
Minikube:

minikube image load hospital-management:1.0

Then restart the deployment.

APPLICATION ERROR:

If the application starts and exits, check:

kubectl logs <pod-name>

Fix the application startup command/configuration.

PORT ERROR:

Check:

kubectl describe pod <pod-name>

Verify the containerPort and the application's real listening port.

CONFIGURATION ERROR:

Check environment variables and required database/configuration values.

RESOURCE ERROR:

Check pod Events and resource-related messages.

STEP 5 — Restart deployment after fixing:

kubectl rollout restart deployment hospital-app

STEP 6 — Watch:

kubectl get pods -w

Wait for:

Running

STEP 7 — Check logs:

kubectl logs <pod-name>

STEP 8 — Check service:

kubectl get services

STEP 9 — Open:

minikube service hospital-app

Troubleshooting flow:

get pods
→ describe pod
→ logs
→ events
→ identify cause
→ fix
→ rollout restart
→ verify Running
→ verify service

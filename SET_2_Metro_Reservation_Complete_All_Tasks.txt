A22. DOCKER SCENARIO QUESTIONS
------------------------------------------------------------

1. What happens if MySQL stops while passengers are accessing the
Metro Reservation application?

Answer:
Database-dependent operations fail because the application cannot
read or write reservation data. The application container may remain
running, but database operations become unavailable.

2. How can reservation data be preserved after deleting MySQL?

Answer:
Use a persistent Docker volume mounted to:

/var/lib/mysql

For example:

-v metro-mysql-data:/var/lib/mysql

The container can be deleted and recreated using the same volume.

3. Why use separate application and MySQL containers?

Answer:
They are independent services. The application and database can be
managed, restarted, scaled and updated separately.

4. How can unauthorized access to passenger/reservation information
be prevented?

Answer:
Restrict database exposure, avoid publishing MySQL port unnecessarily,
use strong database credentials, use a private Docker network and
apply proper application authentication and authorization.

5. How troubleshoot application-to-MySQL connection failure?

Check:

docker ps
docker logs metro-app
docker logs metro-mysql
docker network inspect metro-network

Verify:
- MySQL container is running.
- Both containers share the same network.
- Database hostname is metro-mysql.
- Port is 3306.
- Database name/user/password are correct.
- MySQL has completed initialization.

B10. JENKINS SCENARIO QUESTIONS
------------------------------------------------------------

1. What happens if a developer introduces compilation errors?

Answer:
Jenkins checks out the changed GitHub code and runs the Maven build.
If compilation fails, Maven returns a failure and Jenkins marks the
build as failed. The console output shows the compilation error.

2. How can Jenkins detect GitHub changes?

Answer:
Use a build trigger such as Poll SCM. Jenkins periodically checks
the configured repository/branch for changes.

3. Difference between generating WAR and deploying on Tomcat?

Answer:
Generating the WAR only creates the packaged web application.
Deployment means copying/running that WAR in a web server such as
Tomcat so users can access it.

4. Why is Maven useful?

Answer:
Maven manages dependencies, compiles the project, runs tests and
packages the application using the pom.xml configuration instead of
manually downloading JAR files.

5. How troubleshoot an incorrect pom.xml?

Answer:
Open Jenkins Console Output and find the first Maven error.
Check:
- XML syntax
- groupId/artifactId/version
- dependencies
- plugins
- Java version
- packaging
- repository URLs

Then fix pom.xml and run:

mvn clean package

After it succeeds, run the Jenkins build again.

C14. NAGIOS SCENARIO QUESTIONS
------------------------------------------------------------

1. How identify whether the Metro Reservation server is running/down?

Answer:
Nagios uses host/service checks. If the monitored service or host
does not respond within configured limits, Nagios changes the status
from OK to WARNING/CRITICAL depending on the check.

2. Difference between WARNING and CRITICAL?

Answer:
WARNING means the monitored value has crossed a warning threshold
or has a problem that is not considered severe enough for critical.
CRITICAL indicates a serious failure or a critical threshold.

3. What happens if CPU reaches 100%?

Answer:
The server can become slow and requests may be delayed or fail.
Nagios can detect high load/CPU through the configured monitoring
plugin and produce an alert.

4. How identify application unavailable while server is running?

Answer:
Monitor the application service itself, for example with an HTTP
check. The EC2/server can remain up while the HTTP/Tomcat service
returns an error or stops.

5. How identify Tomcat vs MySQL vs server failure?

Answer:
Use separate checks:
- Host check → server/network availability
- HTTP/Tomcat check → web application availability
- MySQL check → database availability
- Network connectivity checks → communication problems

D13. KUBERNETES SCENARIO QUESTIONS
------------------------------------------------------------

1. What happens if one Pod crashes?

Answer:
The Deployment controller notices that the actual number of Pods
is below the desired number and creates a replacement Pod.

2. How does Kubernetes maintain the desired replicas?

Answer:
A Deployment continuously compares the desired state with the
actual state and creates/removes Pods as required.

3. Difference between scaling up and scaling down?

Answer:
Scaling up increases the number of application replicas.
Scaling down decreases the number.

Example:

2 → 5 = scale up

5 → 2 = scale down

4. How does more replicas help during peak reservation hours?

Answer:
Requests can be handled by multiple application instances instead
of one instance, improving capacity and reducing the load on each Pod.

5. How can Kubernetes distribute requests?

Answer:
A Kubernetes Service provides a stable endpoint and routes traffic
to the Pods selected by its labels.

E22. AWS SCENARIO QUESTIONS
------------------------------------------------------------

1. Why can't passengers access the application using EC2 public IP?

Possible reasons:
- EC2 instance is not running.
- Security Group does not allow the application port.
- Tomcat is stopped.
- Application was not deployed correctly.
- Wrong public IP is being used.
- Application is listening on a different port.
- Network/routing configuration is incorrect.

2. Why configure HTTP/application ports in Security Group?

Answer:
The Security Group acts as a network access filter. If the application
port is not allowed inbound, internet users cannot reach the service
even if the application is running.

3. What happens if Tomcat stops while EC2 is running?

Answer:
The EC2 server remains running, but the web application becomes
unavailable because the Tomcat service is not accepting requests.

4. How make the application available if EC2 fails?

Answer:
Use multiple EC2 instances with load balancing and health checks.
An Application Load Balancer can route users to healthy instances.
Auto Scaling can maintain the required number of instances.

5. Advantages of AWS over a local server?

Answer:
AWS provides remote internet access, flexible compute resources,
monitoring, easier scaling and cloud infrastructure services without
requiring the application server to be physically hosted locally.

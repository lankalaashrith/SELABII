------------------------------------------------------------
DOCKER SCENARIO ANSWERS
------------------------------------------------------------

1. What happens if MySQL stops while students are accessing AI-OLMS?

The AI-OLMS container can remain running, but database-dependent operations such as login, course access or enrolment may fail because the database server is unavailable.

2. How can student/course information be preserved after deleting MySQL?

Use a persistent Docker volume and mount it to:

/var/lib/mysql

For example:

ai-olms-mysql-data:/var/lib/mysql

3. Why separate application and database containers?

Separation makes the system easier to manage, update, restart and scale. Application and database services are isolated from each other.

4. How can student login credentials and course information be protected?

Use authentication, strong database passwords, restricted database access, network isolation, HTTPS/TLS, proper permissions and avoid exposing MySQL directly to the Internet.

5. How troubleshoot database connection failure?

Check:
docker ps

Check network:
docker network inspect ai-olms-network

Check MySQL logs:
docker logs ai-olms-mysql

Check application logs:
docker logs ai-olms-app

Confirm:
- MySQL is running
- Both containers use the same Docker network
- Database hostname is ai-olms-mysql
- Port is 3306
- Database name/user/password are correct

JENKINS SCENARIO ANSWERS
------------------------------------------------------------

1. What happens if a developer introduces compilation errors?

Jenkins runs the Maven build. Maven reports the compilation error and Jenkins marks the build as failed.

2. How can Jenkins automatically detect GitHub changes?

Use a build trigger such as Poll SCM. Jenkins periodically checks the configured repository for changes.

3. Difference between generating WAR and deploying to Tomcat?

Generating the WAR only creates the deployable web application package. Deployment means placing that WAR into a Tomcat server and running the application.

4. Why is Maven useful?

Maven manages dependencies, compiles source code, runs tests and packages the application.

5. How identify and resolve a failed Jenkins build?

Open Console Output, locate the Maven error, correct the code/configuration/dependency problem, then run Build Now again.

------------------------------------------------------------
NAGIOS SCENARIO ANSWERS
------------------------------------------------------------

1. How can Nagios identify whether the AI-OLMS server is running/down?

Nagios performs host/service checks at configured intervals. If checks succeed, the service is OK. If checks fail repeatedly, Nagios reports a problem.

2. Difference between WARNING and CRITICAL?

WARNING means a monitored value has crossed a warning threshold but the service may still be operating.

CRITICAL means the service/resource has reached a serious failure threshold or is unavailable.

3. What if CPU reaches 100%?

The server may become slow or unresponsive. Nagios can report a WARNING/CRITICAL state based on configured thresholds.

4. How detect application failure while server is running?

Use an HTTP/service check. The server may be alive, but if Tomcat/AI-OLMS is unavailable, the HTTP check fails.

5. How identify Tomcat vs MySQL vs server failure?

Use separate checks:
- Host/server check
- HTTP/Tomcat check
- MySQL/database check

Compare the results to isolate the failed component.

STEP 4 — CREATE DEPLOYMENT YAML
------------------------------------------------------------

Create:

ai-olms-deployment.yaml

Use:

apiVersion: apps/v1
kind: Deployment
metadata:
  name: ai-olms-app
spec:
  replicas: 2
  selector:
    matchLabels:
      app: ai-olms
  template:
    metadata:
      labels:
        app: ai-olms
    spec:
      containers:
      - name: ai-olms-container
        image: ai-olms-app:1.0
        imagePullPolicy: IfNotPresent
        ports:
        - containerPort: 8080

------------------------------------------------------------
KUBERNETES SCENARIO ANSWERS
------------------------------------------------------------

1. What happens if one AI-OLMS pod crashes?

Kubernetes detects that the actual number of running pods is below the desired number and creates a replacement pod.

2. How does Kubernetes maintain desired replicas?

The Deployment continuously compares the desired state with the current state and creates/removes pods as needed.

3. Difference between scaling up and scaling down?

Scaling up increases the number of application replicas.

Scaling down decreases the number of replicas.

4. How do more replicas improve performance?

Requests can be handled by multiple application instances instead of relying on a single instance, reducing the load on each instance during peak periods.

5. How does a Kubernetes Service distribute requests?

A Service provides a stable access point and routes traffic to available pods selected by its labels.

------------------------------------------------------------
AWS SCENARIO ANSWERS
------------------------------------------------------------

1. Why might students be unable to access AI-OLMS through the EC2 public IP?

Possible causes:
- EC2 instance is stopped
- Status checks failed
- Tomcat is stopped
- Application failed to deploy
- Wrong public IP
- Security Group does not allow the required port
- Wrong application URL/context path
- Application/database connection failure

2. Why configure HTTP and Tomcat ports in the security group?

The security group acts as a network access control layer. It must allow incoming traffic to the port on which the web application is listening.

For direct Tomcat access, port 8080 must be allowed.

3. What happens if Tomcat stops while EC2 is running?

The EC2 virtual machine remains running, but the AI-OLMS web application becomes unavailable because the application server is stopped.

4. How make AI-OLMS available if EC2 fails?

Use multiple EC2 instances and a load balancer such as an Application Load Balancer. This avoids depending on one EC2 instance.

5. Advantages of AWS over a local server?

AWS provides remote access, scalable infrastructure, monitoring, flexible resource options and easier deployment of services without depending on one physical local machine.

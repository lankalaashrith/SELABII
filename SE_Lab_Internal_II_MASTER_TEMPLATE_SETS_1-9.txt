SOFTWARE ENGINEERING LAB INTERNAL II
MASTER TEMPLATE SOLUTION — SETS 1 TO 9
============================================================

PURPOSE
-------
This is a reusable practical template for the Lab Internal II sets.
The sets repeat the same core tools, but the application, image, port,
artifact type, pipeline style, and required deployment steps can change.

IMPORTANT EXAM RULE:
Do NOT blindly copy every command.
First identify the application type in the question, then select the
matching branch below.

QUICK DECISION TABLE
--------------------
Docker application:
  WordPress + MySQL       -> use WordPress/MySQL commands
  Java Web WAR + MySQL     -> use Tomcat + WAR + MySQL commands
  Flask + Nginx            -> use Flask port 5000 + Nginx port 80
  Web image + Nagios       -> use Docker Compose with web + Nagios

Java artifact:
  .jar -> java -jar target/app.jar
  .war -> deploy to Tomcat webapps/

Jenkins:
  Freestyle -> Configure project in Jenkins UI
  Scripted Pipeline -> Jenkinsfile with node/stage/sh
  Pipeline View / OLTRS -> Jenkinsfile + webhook + Maven + Docker

Kubernetes:
  Existing Docker Hub image -> image: username/app:tag
  Local Docker image        -> build first, then deploy
  Required replicas         -> change replicas or kubectl scale
  Browser access             -> NodePort + minikube service

AWS:
  Static HTML -> Nginx Docker container
  Maven WAR   -> Docker/Tomcat container or Tomcat deployment
  App port 8080 -> Security Group TCP 8080
  App port 9090 -> Security Group TCP 9090
  HTTP         -> TCP 80
  SSH          -> TCP 22, preferably My IP

------------------------------------------------------------
SET 1 TASK 1 — DOCKER
------------------------------------------------------------

1. Check Docker

docker --version
docker ps

2. Pull images

docker pull mysql:5.7
docker pull wordpress:latest

3. Create network

docker network create library-network

4. Create persistent volume

docker volume create mysql-data

5. Run MySQL

docker run -d --name mysql --network library-network \
-e MYSQL_ROOT_PASSWORD=root \
-e MYSQL_DATABASE=wordpress \
-e MYSQL_USER=wpuser \
-e MYSQL_PASSWORD=wppass \
-v mysql-data:/var/lib/mysql mysql:5.7

6. Run WordPress

If port 8080 is free:
docker run -d --name wordpress --network library-network -p 8080:80 \
-e WORDPRESS_DB_HOST=mysql:3306 \
-e WORDPRESS_DB_USER=wpuser \
-e WORDPRESS_DB_PASSWORD=wppass \
-e WORDPRESS_DB_NAME=wordpress wordpress:latest

If 8080 is occupied:
docker run -d --name wordpress --network library-network -p 8081:80 \
-e WORDPRESS_DB_HOST=mysql:3306 \
-e WORDPRESS_DB_USER=wpuser \
-e WORDPRESS_DB_PASSWORD=wppass \
-e WORDPRESS_DB_NAME=wordpress wordpress:latest

7. Verify

docker ps
docker network inspect library-network
docker volume ls

8. Browser

http://localhost:8080
OR
http://localhost:8081

9. MySQL failure

docker stop mysql
docker ps

10. Recovery

docker start mysql
docker ps

11. Delete container but preserve database

docker rm -f mysql
docker volume ls

DO NOT delete mysql-data.

12. Recreate MySQL using same volume

docker run -d --name mysql --network library-network \
-e MYSQL_ROOT_PASSWORD=root \
-e MYSQL_DATABASE=wordpress \
-e MYSQL_USER=wpuser \
-e MYSQL_PASSWORD=wppass \
-v mysql-data:/var/lib/mysql mysql:5.7

The data survives because:
mysql-data -> /var/lib/mysql

docker exec nagios /opt/nagios/libexec/check_disk -w 20% -c 10%

free > 20% = OK
free <= 20% = WARNING
free <= 10% = CRITICAL

10. Load plugin

docker exec nagios ls /opt/nagios/libexec/check_load

If available:
docker exec nagios /opt/nagios/libexec/check_load

TASK 2 — EMAIL NOTIFICATION
---------------------------

Install/configure Email Extension Plugin.

In Jenkins:
Manage Jenkins -> Plugins -> Available plugins
Search:
Email Extension

Configure SMTP in Jenkins system settings.

Pipeline example:

post {
    failure {
        emailext(
            subject: "BUILD FAILED: ${env.JOB_NAME}",
            body: "Build failed: ${env.BUILD_URL}",
            to: "team@example.com"
        )
    }

    success {
        emailext(
            subject: "BUILD SUCCESS: ${env.JOB_NAME}",
            body: "Build succeeded: ${env.BUILD_URL}",
            to: "team@example.com"
        )
    }
}

For a Scripted Pipeline, use try/catch/finally if the exact question
requires a Scripted Pipeline:

node {
    try {
        stage('Checkout') {
            git 'REPOSITORY_URL'
        }

        stage('Build') {
            sh 'mvn clean package'
        }

    } catch (err) {
        emailext(
            subject: "Hospital Build FAILED",
            body: "Build failed: ${env.BUILD_URL}",
            to: "team@example.com"
        )
        throw err
    }
}

-------------------------

Repository:
https://github.com/archanareddyse/OLTRS.git

Required flow:

Checkout
-> Maven Build
-> Test
-> WAR
-> Tomcat
-> Docker Build
-> Docker Push
-> Email result

Scripted Pipeline template:

node {

    stage('Checkout') {
        git 'YOUR-FORK-URL'
    }

    stage('Build') {
        sh 'mvn clean package'
    }

    stage('Test') {
        sh 'mvn test'
    }

    stage('Deploy to Tomcat') {
        sh 'cp target/*.war /path/to/tomcat/webapps/'
    }

    stage('Docker Build') {
        sh 'docker build -t USERNAME/oltrs:latest .'
    }

    stage('Docker Push') {
        withCredentials([
            usernamePassword(
                credentialsId: 'dockerhub-creds',
                usernameVariable: 'DOCKER_USER',
                passwordVariable: 'DOCKER_PASS'
            )
        ]) {
            sh '''
              echo "$DOCKER_PASS" | docker login -u "$DOCKER_USER" --password-stdin
              docker push USERNAME/oltrs:latest
            '''
        }
    }

    stage('Email') {
        echo 'Pipeline completed'
    }
}

If Jenkins agent is Windows, replace sh with bat where required.

IMPORTANT:
The Docker Build/Push stages should happen only after Maven build/test succeeds.
If the Build stage fails, the pipeline stops and later stages are skipped.

DOCKER
------

docker compose down

do not expose DB port publicly; use private Docker network,

-------

Compilation error:
Maven reports compilation failure and Jenkins marks build failed.

Tests fail after compilation:
test phase fails; package/deployment after that does not safely proceed.

dependency management, repeatable builds, standard lifecycle.

Specific branch:
configure branch specifier:
*/branch-name

CI vs CD:
CI automatically integrates/builds/tests changes.
CD automatically delivers/deploys successful changes.

----------

Pod crashes:
Deployment creates a replacement Pod.

Desired replicas:
Deployment/ReplicaSet controller maintains the desired count.

Manual scaling:
administrator changes replicas.

Automatic scaling:

Service:
stable network endpoint for Pods and traffic distribution.

kubectl rollout status deployment/app

kubectl rollout undo deployment/app


NAGIOS
------

High CPU:
Nagios plugin checks CPU/load against configured threshold.

WARNING vs CRITICAL:
WARNING = problem condition but less severe.
CRITICAL = serious threshold or service failure.

Server running but application down:
HTTP/service check detects application failure.

Tomcat vs MySQL vs server:

server health
Tomcat process/port
MySQL process/port
HTTP response
logs.


AWS
---

EC2 inaccessible:
check instance state, public IP, Security Group, route/network,

EC2 remains Running, but web application becomes unavailable.

Availability:
multiple EC2 instances + Load Balancer.

Persistent data:
use appropriate persistent storage such as EBS for EC2-hosted data.

SSH restriction:
TCP 22 from administrator's IP rather than public internet.
